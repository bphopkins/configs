## 5. Pitfalls met in build chat 1, so you do not

- The golden is the specification. The first run failed on one row and
  the parser was wrong, not the golden; look at a diff that way first.
- A Python patch script in a quoted heredoc still interprets `\\` inside
  ordinary string literals: the first patch matched nothing and silently
  changed nothing. Use raw strings and assert the match count before
  writing.
- `cat -A` prints `$` at every line end; it is not an anchor in the file.
- LuaSnip's `from_lua` loader treats a subdirectory of the collection as a
  filetype named after it; anything you put under `lua/snippets/` is
  registered that way until stage 3 changes the loader call.
- `nvim --clean -l script.lua args` runs a Lua script hermetically with
  `arg`; the suite's shape check uses it with stub modules, since
  `snippets.helpers` does not exist yet.
- The closure spike (`spikes/xref2.py`) excludes any row with a `*`
  anywhere in its classification; `#beginEnv*` is not unusual. Its counts
  are a cross-check, not the truth.
- The generator prints warnings to stderr and never fails on data; read
  the warning list after every `--all`, it is short.
- A `.lua` under `tests/` is outside `nvim/.styluaignore`; the suite's own
  `.styluaignore` (`golden/`) is what keeps format-on-save off the goldens.
